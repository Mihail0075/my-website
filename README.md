# Брза Пратка — пратки Прилеп ⇄ Скопје со автобус

Систем за праќање пратки со автобуската линија: **киоск со сандаци**, **шалтер**, **режим за возач** и **админ-панел**, на македонски и англиски.

> Спецификацијата, одлуките и отворените прашања се во [`docs/SPECIFIKACIJA.md`](docs/SPECIFIKACIJA.md).
> Продолжувате на друг компјутер или во нова сесија? Почнете од [`docs/PRODOLZUVANJE.md`](docs/PRODOLZUVANJE.md): сите барања и одговори од разговорот, состојба и следни чекори.

## Што има во оваа верзија

| Дел | Адреса | Кој го користи |
|---|---|---|
| Киоск (touch екран на станица) | `/kiosk` | Праќачи и примачи. Возачот со службен PIN (копче „Персонал“) |
| Шалтер | `/staff/counter` | Шалтерски работник (Прилеп) |
| Возач (на телефон) | `/staff/driver` | Возач |
| Админ: пратки, сандаци (симулатор), киоски, пораки | `/staff/admin` | Администратор |
| Налепница за печатење (100 × 150 mm) | `/staff/label/<id>` | Шалтер/возач |
| Праќање онлајн (QR на станицата) | `/send?from=SK` | Праќачи на телефон |
| Страница за примачот (PIN + QR) | `/pickup/<token>` | Примач (линк во пораката) |

Плаќањето со картичка е **симулирано** (означено „ТЕСТ РЕЖИМ“), а сандаците се **симулирани** додека не се поврзе хардверот. Види [`docs/HARDWARE.md`](docs/HARDWARE.md).

## Технологија

Next.js 16 (React 19, TypeScript), Tailwind CSS 4, PostgreSQL + Drizzle ORM, Vitest.

## Стартување локално

Потребно: Node.js 22+ и PostgreSQL 14+.

```bash
npm install
cp .env.example .env          # пополнете DATABASE_URL и SESSION_SECRET
npm run db:migrate            # креира табели
npm run db:seed               # 2 станици, по 30 сандаци, корисници admin / salter.prilep / vozac
npm run dev                   # http://localhost:3000
```

`db:seed` генерира и **еднаш испишува** лозинки, службени PIN-ови и клучеви за контролерите. Запишете ги. За демо може да ги зададете однапред:

```bash
SEED_ADMIN_PASSWORD=... SEED_ADMIN_PIN=123456 SEED_COUNTER_PASSWORD=... \
SEED_DRIVER_PASSWORD=... SEED_DRIVER_PIN=654321 npm run db:seed
```

### Активирање на киоск

1. На уредот што ќе биде киоск, отворете `/staff/login` и најавете се како `admin`.
2. **Киоски** → „Активирај го овој уред како киоск за Скопје“. Уредот оди на `/kiosk/SK`.
3. Одјавете се. Уредот останува киоск (колачето трае 5 години). Со „Одјави ги сите киоски“ се поништуваат сите уреди на таа станица.

Во продукција прелистувачот на киоскот треба да работи во kiosk-режим (на пр. `chromium --kiosk https://.../kiosk`), со вклучена тастатура на екран на оперативниот систем.

### Пробување на целиот тек (симулација)

1. **Шалтер** (`salter.prilep`): нова пратка Прилеп → Скопје, наплати готовина. Го добивате бројот на пратката и PIN-от.
2. **Киоск Прилеп** → „Персонал“ → PIN на возачот → „Земи“.
3. **Киоск Скопје** → „Персонал“ → PIN на возачот → „Во сандак“ → „Ставено ✓“.
4. **Киоск Скопје** → „Подигни пратка“ → PIN → се отвора сандакот.
5. **Админ → Сандаци**: во живо се гледа кој сандак е зафатен или отворен. **Админ → Пораки**: е-поштата што би била испратена.

| Команда | Што прави |

## Структура

```
src/
  app/
    kiosk/              киоск (екран на допир)
    staff/              најава, шалтер, возач, админ, налепница
    (site)/             јавни страници: праќање онлајн, плаќање, следење, страница за примач
    api/                JSON API (kiosk/, staff/, parcels/, hw/ за контролерот на сандаците)
  components/           UI (kiosk/, staff/, SendForm …)
  db/schema.ts          табели (станици, сандаци, пратки, настани, корисници, сесии …)
  lib/
    config.ts           цени, големини, рокови ← деловни правила на едно место
    services/parcels.ts целиот животен тек на пратката
    services/lockers.ts доделување/отворање сандаци, протокол за хардвер
  i18n/                 mk.ts и en.ts, сите текстови
hardware/controller.py  референтен контролер за Raspberry Pi (нетестиран на хардвер)
docs/                   спецификација, хардвер, безбедност
tests/                  тестови на сервисите
```

## Поставување на сервер (продукција)

- Променливи: `DATABASE_URL`, `SESSION_SECRET` (долг случаен низ, `openssl rand -hex 32`), `APP_URL` (јавната адреса, се користи во QR кодовите и пораките), `SMTP_*`, `MAIL_FROM`, `LOCKER_MODE=hardware` кога ќе се поврзат сандаците, `PAYMENT_MODE=live` кога ќе се поврзе вистинска платежна порта (ја исклучува симулацијата).
- Опција А: **Vercel** (Next.js) + управувана PostgreSQL база (Neon, Supabase…) во ЕУ.
- Опција Б: **VPS** (на пр. Hetzner): Node 22 + PostgreSQL + nginx со HTTPS.
- По секое ажурирање: `npm run db:migrate`.
- Дневна резервна копија на базата (`pg_dump`).
